# K230 视觉模块 + ESP32 联网主控设计

## 1. 目标与范围

将现有系统拆分为两个职责清晰的设备：

- K230 V3.0：连接摄像头，执行本地视觉推理，输出识别结果；
- ESP32-S3：负责 Wi-Fi、云端多模态模型、网页接口、传感器和执行器控制。

ESP32 不再直接使用 OV2640。K230 的本地推理结果作为常规数据流；只有用户请求或本地事件触发时，K230 才向 ESP32 发送一帧 JPEG，ESP32 再上传百炼视觉模型。

本阶段不包含 K230 与 ESP32 之间的视频连续流，也不把 API Key 写入 K230。

## 2. 资料依据与硬件边界

方案依据目录 `E:\K230 V3.0 开发板客户资料 2024-8-19`：

- `4.原理图\k230  3.0引脚图.jpg`：40 针排针提供 UART2_TXD(GPIO5，排针17) 和 UART2_RXD(GPIO6，排针18)；
- `2.文档\k230引脚调用.txt`：GPIO5/6 可复用为 UART2_TXD/RXD；
- `3.应用案例\14-Socket`：K230 MicroPython 支持 WLAN、TCP、UDP、HTTP；
- `2.文档\face_detection.py` 及 `3.应用案例\04-AI-Demo`：K230 可运行摄像头和 NPU 视觉推理示例。

两块板使用 3.3 V TTL UART，必须共地并交叉连接：

```text
K230 UART2_TXD / GPIO5 / 排针17  -> ESP32 右侧 G2（RX）
K230 UART2_RXD / GPIO6 / 排针18  -> ESP32 右侧 G1（TX）
K230 GND                         -> ESP32 右侧 GND
```

K230 和 ESP32 建议分别供电，不从 ESP32 的 3.3 V 引脚给 K230 主板供电；信号线上不得接入 5 V。你这块 GOOUUU ESP32-S3-CAM V1.3 的右侧排针直接标有 G1、G2、GND，本工程使用 G1 作为 TX、G2 作为 RX。

## 3. 系统架构

```text
K230 摄像头 -> 本地 NPU 推理 -> UART 二进制帧 -> ESP32 主控
                                      |             |
                                      |             +-> Wi-Fi / 网页 / 外设
                                      |
                         事件或用户请求时发送 JPEG
                                                    |
                                                    +-> 百炼视觉模型
```

### K230 端职责

1. 初始化摄像头和选定的视觉模型；
2. 按固定周期运行推理；
3. 将人脸、目标、OCR 等结果压缩为短 JSON；
4. 接收 ESP32 的拍照命令；
5. 采集一帧 JPEG，按分块帧发送；
6. 维护心跳和串口重同步。

### ESP32 端职责

1. 初始化 UART 链路和 Wi-Fi STA；
2. 接收并校验 K230 的结果帧；
3. 向网页、传感器和执行器提供统一状态；
4. 通过命令请求 K230 拍照；
5. 重组 JPEG 并通过 HTTPS 上传百炼视觉模型；
6. 返回识别文字或结构化结果。

## 4. UART 协议

UART 初始参数固定为 `921600 8N1`；若实际线缆或转接板不稳定，降级为 `460800 8N1`。所有多字节整数使用小端序。

### 4.1 通用帧格式

```text
偏移  字段       长度
0     magic      2       固定 0xA5 0x5A
2     version    1       当前为 0x01
3     type       1       消息类型
4     length     2       Payload 字节数
6     sequence   2       发送序号
8     payload    length  负载
8+N   crc16      2       从 version 到 payload 的 CRC16-CCITT
```

### 4.2 消息类型

| 类型 | 方向 | 作用 |
|---:|---|---|
| `0x01` | K230 -> ESP32 | 本地视觉结果 JSON |
| `0x02` | 双向 | 心跳/链路状态 |
| `0x10` | ESP32 -> K230 | 请求拍照并发送 JPEG |
| `0x11` | K230 -> ESP32 | JPEG 数据块 |
| `0x12` | K230 -> ESP32 | JPEG 发送结束，包含总长度和 CRC32 |
| `0x13` | ESP32 -> K230 | JPEG 接收确认 |
| `0x7F` | 双向 | 错误报告 |

本地结果 JSON 示例：

```json
{"task":"face","count":1,"items":[{"x":320,"y":180,"w":96,"h":120,"score":0.92}]}
```

JPEG 分块建议每块不超过 2048 字节。ESP32 只为当前一张图片分配缓冲区，默认上限为 256 KiB；超过上限立即丢弃并返回错误，避免内存被异常数据耗尽。

`0x11` 的 Payload 为 `request_id(uint16) + offset(uint32) + data`，其中 `data` 不超过 2048 字节；`0x12` 的 Payload 为 `request_id(uint16) + total_length(uint32) + crc32(uint32)`。

## 5. 工作流程

### 5.1 启动与链路建立

1. ESP32 启动 UART、Wi-Fi 和网页服务；
2. K230 初始化摄像头和模型；
3. 双方每 2 秒发送一次心跳；
4. 连续 3 个心跳周期未收到对端数据时标记链路断开；
5. 链路恢复后，双方重新发送设备能力和当前模型名称。

### 5.2 常规视觉结果

K230 按 5--10 FPS 推理，但只在结果变化或每 200 ms 至少发送一次摘要，避免 UART 被重复 JSON 占满。ESP32 保存最近一条有效结果及时间戳，网页显示“结果年龄”。

### 5.3 云端视觉请求

1. 用户访问 ESP32 `/analyze`，或本地规则触发云端分析；
2. ESP32 发送 `0x10` 拍照命令和请求序号；
3. K230 暂停或降低常规推理，采集一帧 JPEG；
4. K230 发送 `0x11` 分块和 `0x12` 完成帧；
5. ESP32 校验长度与 CRC32 后调用百炼视觉模型；
6. ESP32 返回中文描述，并发送 `0x13` 释放 K230 的发送状态；
7. K230 恢复常规推理。

单次 JPEG 请求设置 10 秒超时；超时、CRC 错误或长度超限时不得调用云端。

## 6. ESP32 软件边界

现有摄像头模块不再参与主流程。新增模块建议保持以下边界：

- `K230_LINK`：UART 驱动、帧编解码、CRC、重同步；
- `VISION_STATE`：最近视觉结果、链路状态和 JPEG 缓冲；
- `LLM`：沿用现有 HTTPS 百炼调用，但输入改为 K230 JPEG；
- `WEB`：保留预览/状态页，`/analyze` 改为请求 K230 拍照。

ESP32 不应解析 K230 模型的内部输出格式，只解析协议规定的 JSON；更换人脸、目标或 OCR 模型不应影响 ESP32。

## 7. K230 软件边界

K230 端以资料中的 MicroPython 示例为基础：

- 摄像头和推理沿用 `face_detection.py`、`04-AI-Demo` 的 `PipeLine`/`AIBase` 模式；
- UART 使用 `machine.FPIOA` 将 GPIO5/6 复用为 UART2；
- 串口协议和 JPEG 分块独立封装，不将云端 API、Wi-Fi 凭据或 ESP32 业务逻辑放入模型类。

K230 端首个可交付模型选择人脸检测或目标检测，先验证链路；OCR 和更复杂模型作为后续能力，不与 UART 联调同时引入。

## 8. 错误与安全策略

- 帧头错误：逐字节搜索 `0xA5 0x5A` 重新同步；
- 长度大于 256 KiB：立即丢弃整帧并发送 `0x7F`；
- CRC 错误：丢弃本帧，要求重发或重新拍照；
- K230 离线：ESP32 网页显示链路断开，不调用云端；
- 云端失败：保留本地视觉结果，返回明确的网络/API 错误；
- API Key 仅存在 ESP32 的本地配置/后端，不发送给 K230；
- JPEG 和 JSON 内容只在内存中短暂保存，不写入 Flash。

## 9. 验证标准

### 阶段一：硬件链路

- UART 收发 1000 帧无 CRC 错误；
- 拔插 K230 后 ESP32 能在 6 秒内显示离线/恢复状态；
- 921600 波特率不稳定时可切换 460800。

### 阶段二：本地视觉

- K230 连续运行 10 分钟，人脸/目标结果持续到达；
- ESP32 网页显示结果、置信度和时间戳；
- 不连接云端时系统仍能完成本地识别。

### 阶段三：云端视觉

- ESP32 `/analyze` 能触发一次 JPEG 请求；
- 320--640 宽度 JPEG 在 10 秒内完成接收和 HTTPS 请求；
- API Key 错误、网络断开、JPEG 超限均能返回可诊断错误；
- K230 本地推理在云端请求结束后自动恢复。

## 10. 实施顺序

1. 先用固定字符串验证 K230 UART2 到 ESP32 UART 的双向帧；
2. 加入 CRC16、心跳和断线重同步；
3. 接入 K230 人脸检测，发送结果 JSON；
4. 接入 JPEG 拍照分块；
5. 修改 ESP32 `/analyze` 使用 K230 JPEG；
6. 最后再加入 OCR、目标检测和事件规则。
