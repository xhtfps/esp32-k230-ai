# K230「星云智脑」LVGL 二级助手页设计

## 1. 目标

在 CanMV K230 V3.0（CanMV v1.2.2）的现有摄像头预览之上，增加一个 800×480 横屏、可触控的 LVGL 二级 AI 助手页。它是 K230 的会话与视觉信息主界面；ESP32 的 128×160 ST7735 仅显示表情。

页面采用「星云智脑」风格：深海军蓝、青蓝和紫色的低成本霓虹强调色，避免影响摄像头预览的实时性。

## 2. 用户交互

### 2.1 页面切换

- 摄像头预览页是默认主页面，实时视频始终优先。
- 手指从屏幕**右边缘向左滑动**：打开 AI 助手页。
- AI 助手页从屏幕**左边缘向右滑动**：关闭页面，返回预览页。
- 页面切换使用 180--220 ms 的水平滑动；不使用全屏模糊或全屏 Alpha 动画。

### 2.2 助手页内容

页面为覆盖在视频上方的 OSD 二级层，视频在右侧与间隙处保持可见。

| 区域 | 位置 | 内容 |
|---|---|---|
| 链路 HUD | 左上 | Wi-Fi、K230↔ESP32 UART、会话状态的简洁图标/文字 |
| 语音球 | 左侧中央 | 可按住说话；显示会话状态与低成本圆环动效 |
| 转写卡片 | 右上 | 最近一次最终转写，最多两行 |
| 回答卡片 | 右中 | 当前回答或最近回答，最多四行并支持增量更新 |
| 视觉洞察卡 | 右下 | 请求视觉分析按钮、视觉摘要与状态 |
| 返回提示 | 左下 | 左滑返回预览的手势提示 |

语音球状态颜色固定：`IDLE=青蓝`、`LISTENING=青绿`、`TRANSCRIBING/THINKING=紫色`、`SPEAKING=蓝紫`、`ERROR=红色`。动效只改变圆环大小、透明度和线宽，不每帧重建对象。

## 3. 系统分层

以官方 CanMV `ai_lvgl.py` 的「视频层 + OSD/LVGL + 触控 + 独立 AI 线程」模式为基线。

```text
Sensor/Display VIDEO 层 ───────────────> 实时摄像头预览
                                    │
LVGL UI Controller <── App Store <── UART 接收任务（ESP32）
       │                  ^
       │                  └────────── 触控/手势输入任务
       └── OSD/LVGL 图层

视觉推理线程 ──> 视觉摘要/检测框状态 ──> App Store
```

- `video_service`：沿用现有 Sensor、Display、MediaManager 和视频绑定/预览逻辑；不直接改 LVGL 控件。
- `uart_service`：沿用并扩展 `VisionLink`，解析视觉协议与新增会话帧；只投递状态事件。
- `touch_service`：使用 `machine.TOUCH` 采样触点，识别边缘滑动与语音球按住/松开；只投递 UI 动作。
- `app_store`：唯一的会话/链路/文本/视觉摘要状态容器；事件通过有界队列进入。
- `ui_controller`：唯一允许调用 LVGL 控件 API 的组件；在主循环按差量刷新。
- `vision_service`：后续模型推理或 JPEG 请求的生产者；不得阻塞触控或 UI 刷新。

## 4. K230 与 ESP32 会话协议

物理 UART 继续使用 GPIO5 TX → ESP32 GPIO2 RX、GPIO6 RX ← ESP32 GPIO1 TX、921600 8N1、CRC16 帧格式。

| 类型 | 方向 | 含义 |
|---:|---|---|
| `0x20` | K230 → ESP32 | UI 动作：开始说话、结束说话、停止播放、请求视觉分析 |
| `0x21` | ESP32 → K230 | 会话状态：状态码、会话 ID、错误码 |
| `0x22` | ESP32 → K230 | 最终转写 UTF-8 文本 |
| `0x23` | ESP32 → K230 | 回答 UTF-8 增量或最终文本 |
| `0x24` | ESP32 → K230 | 错误码与短说明 |

K230 的语音球按下只发 `START_LISTENING`；松开只发 `STOP_LISTENING`。K230 不采集音频、不保存任何云端密钥。视觉按钮发 `ANALYZE_VISION`，ESP32 再按已有 JPEG 请求机制取图。

## 5. 状态和容错

- 无 UART 心跳超过 3 秒：HUD 标记 ESP32 离线，禁用按住说话与视觉分析，视频预览继续。
- 助手页关闭时仍接收会话状态，但只更新 App Store；重新打开后渲染最新快照。
- 文本长度有边界：转写保留 96 UTF-8 字节，回答保留 384 UTF-8 字节；截断必须显示省略号。
- LVGL 控件创建一次，之后仅更新文本、颜色、可见性与动画状态；不能在 UART/推理任务中直接创建或销毁控件。
- 触控坐标、手势阈值与 API 形式因 CanMV v1.2.2 固件而异，先用独立诊断脚本验证后才接入主程序。

## 6. 实施顺序与验收

1. 从官方示例提炼出可在 v1.2.2 导入的 LVGL/TOUCH 初始化骨架，并做独立导入与触控坐标诊断。
2. 将当前 `k230/main.py` 拆成保留视频预览的 `video_service` 与可独立运行的 `ui_controller`。
3. 实现 App Store、右入左出边缘手势、静态助手页与低成本语音球动效。
4. 扩展 `vision_protocol.py` / `vision_link.py`，接收 `0x21`--`0x24` 并发送 `0x20` UI 动作。
5. 进行双板会话状态验证，最后再接入云端 ASR、LLM、TTS。

验收标准：主预览持续显示；边缘手势可靠切换；AI 页触控延迟小于 100 ms；ESP32 状态在 300 ms 内同步；UART 拔掉或 Wi-Fi 断开时 UI 可恢复且不会停止视频。

## 7. 非目标

- 本阶段不重写现有 K230 摄像头、JPEG 分块或视觉协议的 `0x01`、`0x02`、`0x10`--`0x13` 语义。
- 本阶段不在 K230 上实现 ASR、LLM、TTS 或音频采集。
- 不在首版加入复杂粒子、模糊、全屏半透明混合或无限对话历史，以保护视频与触控流畅度。
