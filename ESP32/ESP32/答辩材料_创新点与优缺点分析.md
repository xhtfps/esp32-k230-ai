# ESP32-S3 + Arduino ATmega328 机器人控制系统

## 一、项目概述

本系统是一个基于 ESP32-S3 和 Arduino ATmega328 的双控制器机器人平台，集成了摄像头视频采集、WiFi 通信、语音播报、姿态识别和舵机控制等功能。系统支持两种运行模式：WiFi+上位机模式（高精度 AI 识别）和本地离线模式（完全自主运行），可根据应用场景灵活切换。

---

## 二、软件创新点

### 2.1 双模架构设计

| 特性 | 说明 |
|------|------|
| **WiFi+上位机模式** | ESP32 采集视频流，通过 WiFi 传输给电脑运行 MediaPipe AI 识别，精度高、功能丰富 |
| **本地离线模式** | ESP32 直接运行简化版姿态识别算法，无需网络和外部设备，适合比赛现场 |
| **一键切换** | 通过修改 platformio.ini 中一行配置即可切换模式，无需修改硬件接线 |

**创新意义**：解决了比赛现场网络不稳定、不允许使用外部设备等问题，同时保留了高精度识别的扩展能力。

### 2.2 统一配置管理（config.h）

| 特性 | 说明 |
|------|------|
| **双方共享** | ESP32 和 ATmega328 共用同一个 config.h，确保通信参数完全同步 |
| **查表法映射** | 语音指令通过 CMD_TABLE 数组映射，添加新动作只需修改配置文件 |
| **条件编译** | 使用 #ifdef ESP32 / #ifdef AVR 区分双方专属配置，避免冲突 |

**创新意义**：传统方案需要分别修改两个控制器的代码，容易出错。本方案实现"一改全改"，降低维护成本。

### 2.3 自适应背景建模算法（离线版）

| 特性 | 说明 |
|------|------|
| **动态更新** | 背景模型在运行时持续更新，适应光照变化 |
| **前景保护** | 只更新差分小于阈值的区域，避免将静止人体融入背景 |
| **滑动平均** | 使用浮点数背景模型，支持渐进式学习 |

**创新意义**：传统背景减除对光照敏感，本算法通过自适应更新提高了鲁棒性。

### 2.4 动作稳定判断机制

| 特性 | 说明 |
|------|------|
| **多帧确认** | 连续 5 帧识别为同一动作才确认，避免误触发 |
| **保持时长判断** | 动作保持 2 秒后才触发语音，防止瞬间动作误报 |
| **冷却时间** | 3 秒冷却防止重复触发同一动作语音 |

**创新意义**：提高了系统在实际场景中的可靠性，避免频繁误触发。

### 2.5 分布式通信协议

| 特性 | 说明 |
|------|------|
| **双串口设计** | ESP32 同时使用 Serial（调试）和 Serial2（通信），互不干扰 |
| **帧格式定义** | SU-03T 语音模块使用 AA 55 <cmd> 55 AA 标准帧格式 |
| **视觉指令协议** | 以 '#' 开头、'\n' 结尾的字符串协议，如 #FACE、#OBJ1 |

### 2.6 查表法指令转发（Arduino 端）

| 特性 | 说明 |
|------|------|
| **循环查表** | 从 90+ 行 switch/case 简化为 15 行循环 |
| **易于扩展** | 添加新动作只需在 config.h 的 CMD_TABLE 中增加一行 |
| **零代码修改** | 无需修改 arduino_receiver.cpp |

## 三、硬件创新点

### 3.1 双控制器架构

| 控制器 | 职责 | 优势 |
|--------|------|------|
| **ESP32-S3** | 视频采集、WiFi、AI识别/通信、语音控制 | 240MHz 双核，带 WiFi/BT，支持 PSRAM |
| **ATmega328** | 指令接收、舵机控制、串口转发 | 实时性好，IO 丰富，成本低 |

**创新意义**：分工明确，ESP32 负责复杂计算，ATmega328 负责实时控制，发挥各自优势。

### 3.2 模块化设计

| 模块 | 功能 | 接口 |
|------|------|------|
| OV2640 摄像头 | 视频采集 | DVP 并行接口 |
| SU-03T 语音模块 | 语音播报 | UART 串口 |
| ESP32-S3 | 主控制器 | WiFi + 双串口 |
| ATmega328 | 协控制器 | SoftwareSerial x2 |
| 舵机控制板 | 执行机构 | UART 串口 |

**创新意义**：各模块通过标准接口连接，便于替换和升级。

### 3.3 低功耗优化

| 措施 | 效果 |
|------|------|
| 灰度图处理 | 数据量减少 2/3 |
| 320x240 分辨率 | 降低计算量 |
| 8MHz XCLK | 降低摄像头功耗 |
| 单帧缓冲 | 节省 PSRAM |

## 四、系统优点

### 4.1 可靠性高

- **离线模式**：不依赖网络，比赛现场稳定运行
- **双模备份**：WiFi 故障时可切换离线模式
- **参数同步**：config.h 确保双方通信参数一致

### 4.2 扩展性强

- **查表法**：添加新动作只需改配置文件
- **模块化**：各功能模块独立，便于替换
- **多环境**：PlatformIO 支持一键切换编译目标

### 4.3 成本低

- **主控芯片**：ESP32-S3 约 30 元，ATmega328 约 15 元
- **摄像头**：OV2640 约 20 元
- **总成本**：控制在 100 元以内

### 4.4 开发效率高

- **统一配置**：避免重复修改
- **调试方便**：串口输出详细日志
- **热切换**：无需重新烧录即可切换模式

### 4.5 实时性好

- **本地处理**：离线模式延迟 < 100ms
- **UDP 通信**：语音指令走 UDP，不阻塞视频流
- **多线程**：上位机使用线程发送姿态数据

## 五、系统缺点与改进方向

### 5.1 离线模式精度有限

| 问题 | 原因 | 改进方案 |
|------|------|---------|
| 受光照影响 | 背景减除对光照敏感 | 增加自适应阈值、使用颜色空间转换 |
| 只能识别明显动作 | 缺少关节级检测 | 引入轻量级神经网络（TensorFlow Lite Micro） |
| 误识别率较高 | 规则分类过于简单 | 增加更多几何特征、使用 SVM 分类器 |

### 5.2 算力瓶颈

| 问题 | 原因 | 改进方案 |
|------|------|---------|
| 帧率低 | ESP32 处理 320x240 图像吃力 | 进一步降低分辨率、使用 ESP32-S3 的向量指令加速 |
| 内存紧张 | 背景模型占用大量 PSRAM | 使用 INT8 量化、分块处理 |

### 5.3 通信带宽限制

| 问题 | 原因 | 改进方案 |
|------|------|---------|
| WiFi 传输延迟 | MJPEG 流占用带宽 | 使用 H.264 编码、降低帧率 |
| 串口速率限制 | SoftwareSerial 最高 115200 | 使用硬件串口、压缩数据包 |

### 5.4 缺乏学习能力

| 问题 | 原因 | 改进方案 |
|------|------|---------|
| 无法适应新动作 | 规则固定 | 增加在线学习模块、记录用户动作样本 |
| 参数调节困难 | 阈值需手动调整 | 增加自动调参算法、遗传算法优化 |

### 5.5 硬件集成度低

| 问题 | 原因 | 改进方案 |
|------|------|---------|
| 接线复杂 | 多模块独立连接 | 设计 PCB 集成板、使用排线接口 |
| 体积较大 | 使用开发板而非裸片 | 定制 PCB、使用更小封装 |

## 六、答辩要点

### 6.1 创新点总结（30 秒版本）

> "本系统实现了双模架构：WiFi+上位机模式精度高，本地离线模式可靠性好。通过统一配置文件实现双控制器参数同步，使用查表法简化指令映射，自适应背景建模提高离线识别鲁棒性。"

### 6.2 应对评委提问

| 可能问题 | 回答要点 |
|---------|---------|
| "为什么不用单芯片？" | 双芯片分工明确，ESP32 负责计算，ATmega328 负责实时控制，发挥各自优势 |
| "离线模式精度够吗？" | 目前基于规则分类，适合明显动作；未来可引入 TensorFlow Lite 提升精度 |
| "为什么用 WiFi 不用蓝牙？" | WiFi 带宽高，适合视频流传输；蓝牙适合短距离控制，带宽不足 |
| "添加新动作麻烦吗？" | 只需在 config.h 的 CMD_TABLE 中加一行，无需修改业务代码 |
| "比赛时网络不好怎么办？" | 可一键切换离线模式，完全不依赖网络 |

### 6.3 演示建议

1. **先演示 WiFi 模式**：展示高精度 AI 识别和流畅视频流
2. **再切换离线模式**：拔掉网线，展示系统仍能正常工作
3. **展示添加动作**：现场修改 config.h，编译上传，演示新动作
4. **展示调试信息**：串口输出动作特征值，体现系统透明度
